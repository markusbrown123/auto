# Equipment and progression

The data and rules layer for real equipment: definitions, ownership, save migration, rewards, the shop, the forge, discovery, set bonuses. Screens are other work; this page is what they code against.

Sources: `data/items.json` (hand-written base list, ids and base numbers) + `data/equipment.json` (generated by `tools/gen_equipment.py`: everything below; **edit the generator, not the JSON**) → merged by `src/core/db.gd`. Rules: `src/core/stats.gd` (numbers handed to the duel), `src/core/rewards.gd` (victory roll), `src/core/game.gd` (profile, economy, queries), `src/combat/duel_sim.gd` (shield count, footwork, guard damage). Tests: `tests/equipment.gd`. Balance: `tools/econ_sim.sh`.

## 1. Item definition (schema)

Every item in `Db.items[id]` has the base fields (`id name slot rarity price desc look`, plus `cls damage element crit` for weapons and `defense hp stamina strength dex crit resist block` where it has them) and the generated ones:

| field | meaning |
|---|---|
| `slot` | `weapon offhand shield helm chest shoulders gauntlets legs boots ring relic` (`Db.EQUIP_SLOTS`; `offhand` has no items yet, see Proposed) |
| `rarity` / `tier` | stored value / the rank shown: common→**common**, uncommon→**uncommon**, rare→**rare**, epic→**legendary**, legendary→**relic**. `Db.tier(it)`, `Db.tier_color(it)`. The stored values are unchanged so old ids, colours and saves work. |
| `family` | `crownless ashbound widow gravekeeper frostwarden dragonforged sovereign architect` (weapons, shields, rings and relics carry one too, for materials and lore) |
| `weight` | armour and shields: `light medium heavy` |
| `shield_class`, `blocks`, `regen`, `mobility` | shields (section 4) |
| `swing`, `cost`, `guard_dmg`, `role`, `role_text` | weapons that differ from their class: swing-time and stamina multipliers, guard-damage multiplier; the four basic swords' role |
| `req` | soft requirement, e.g. `{"strength": 9}` |
| `visual` | what is really drawn today: `suit` (a chest: wearing it swaps the whole knight model), `model` (own mesh), `alias` (another item's mesh, tinted, per `duel.gd`), `none` (numbers only) |
| `model`, `part`, `part_slot`, `part_ready`, `gear_id`, `gear_ready` | visual references: suit/mesh name; the suit id and `ArmorParts` slot of an armour piece and whether that part mesh exists; the name the hand-modelled gear is built under in `assets/models/gear/` and whether it is there |
| `upgrade` | `{max, growth, costs:[{gold, shards, materials}]}` (not on rings/relics) |
| `mods` | weapons: `{grip:[cost×3], ore:[cost×3], sharpen:{gold}}` |
| `mastery` | `{need, marks:[{at, type, ref, text}]}` |
| `sources`, `source`, `hint` | every way to get it, the main one, and a spoiler-free line |
| `unlock`, `unlock_text` | priced items: `{cleared:n}` or `{boss:id}`, and the line shown while locked |
| `craft` | forge pattern `{gold, shards, materials}` |
| `advanced` | Recall-capable (Eternal Edge, King's Remnant, Twin Relics, The Twin Hungers, Glacier Ward) |
| `sell`, `quest_item`, `unsellable`, `set_piece`, `formerly` | sell value; keepsakes; the starting plate does not count towards a set; an earlier name |

## 2. What is real (and what is only proposed)

Everything a screen shows comes from `Stats.compute()` and is read by `duel_sim.gd`; `tests/equipment.gd` proves each by running fights with and without it.

| shown | how it reaches the duel |
|---|---|
| Damage, Swing time, Swing cost, Stamina, Stamina recovery, Health, Defence (→ mitigation), Stagger damage, Guard, Resistance, Element | as before |
| **Weight class** (per armour piece and shield) | light: stamina returns 2% faster, swings cost 1% less. heavy: 2% slower, 1% dearer, guarding costs 1.2% less. medium: nothing |
| **Guard damage** (`guard_dmg`) | multiplies chip damage through a raised guard and the poise each cut wears away (new, small sim hook) |
| **Shield blocks** (`shield_blocks`, `shield_regen`) | section 4 (new sim mechanic) |
| **Footwork** (`dodge_cost`, shown as `footwork` = 100/dodge_cost) | multiplies the stamina a dodge or roll costs (new sim hook) |
| **Requirements** | never a refusal. Unmet weapon: −15% damage, swings 20% dearer. Unmet armour piece: stamina returns 3% slower. `stats().unmet` lists them |
| **Set bonuses** | the table above, all built from the same numbers |
| **Mastery** | weapon mark II: swings 3% cheaper; armour mark II: stamina returns 1% faster while worn; shield mark II: guarding 2% cheaper |
| **Cosmetics** | nothing. `finish`, `accent`, `look_as` never touch a number (tested) |

Keys in the stats dictionary that are descriptions only: `burden` (light/medium/heavy overall), `weights`, `sets`, `unmet`, `footwork`.

**Proposed, not built** (each would need a new sim mechanic, so no display-only stat was invented):
- Player poise / impact resistance from heavy armour (the sim has poise for the foe only; heavy armour's "guarding costs less" is the nearest real thing).
- Dodge and roll *timing* by weight (i-frames and recovery are constants the animation work depends on; only the stamina price changes).
- An `offhand` secondary weapon: the slot exists in saves and rules, no item uses it. Dual blades are one two-handed item; a real off hand needs a weapon-switch or parry-dagger mechanic.
- Guardian-specific sets beyond the eight families; trait properties beyond element and critical on ores.

**Mods at the forge** (`Game.weapon_mods`, `mod`, `mod_cost`, `mod_block`, `mod_preview`). All weapons, not only swords.

| track | tiers | each tier | cost |
|---|---|---|---|
| Blade | 5 | +10% damage, +8% guard damage | gold + shards; the weapon's region material from tier 3 for Rare and above. **This is the old upgrade level** (`profile.upgrades[id]`) |
| Grip | 3 | swings 3% quicker, 5% cheaper | gold + shards |
| Ore | 3: Steel → a region's ore → Cored | +3% damage; sets the caps: blade 2/3/4/5, grip 1/2/3/3 | Steel: gold + 3 shards. Region ore: gold + 4 of the chosen material. Cored: gold + 1 Guardian Core |

The second ore tier is chosen (`ore_id`), and marks the blade: Old Iron +10% guard damage; Grave Silver +4 critical; Wyrm Scale a fire edge and Rimesteel a frost edge (only if the blade has no element); Hollow Glass +6 critical.

The old one-button upgrade still works: `Game.upgrade(weapon)` buys the next blade tier and takes the ore step with it when the blade is at its cap (in the weapon's own material); `Stats.upgrade_cost(it, level)` shows exactly that combined price (tested press by press).

## 4. Shields

Each shield stops `blocks` blows, then it is **spent**: the next blow caught costs twice the stamina and 35% of it gets through (the existing guard-break still applies if stamina runs out). One block returns for every `regen` seconds the guard is down; a shield held up does not recover. **A timed block costs no charge.** A two-handed blade has no count (guarding with it is as it was). `mobility` multiplies the stamina a dodge or roll costs. Every two upgrade levels add one block.

| Splintered Heater | heater | medium | 3 | 4.0s | ×1.00 | start |

## 5. Rewards (`Rewards.roll`, applied by `Game.on_victory`)

Seeded from the journey's seed, the foe and how often it has fallen: the same victory always pays the same, and losing changes nothing (a loss gives nothing and does not re-roll what is waiting).

- **Always**: experience, gold, shards (1; a guardian 3 + one for each region before its own), mastery for everything worn.
- **Materials**: the region's material (ordinary foe 65% for 1, elite 2, guardian 4) and one **Guardian Core** per guardian per cycle.
- **Guardians**: the guaranteed first-kill reward in `Db.equipment.boss_rewards[id].first`; each `pool` entry at its chance; `unlocks` opened in the shop. A guaranteed item already held pays 25% of the foe's gold and 2 material instead. Re-kills never duplicate.
- **Optional encounters** (`Db.equipment.encounters`): eight foes that only sometimes walk a road each carry one exclusive piece.
- **Ordinary drops**: 10% (elite 22%) for a piece of that region's ordinary stock.
- **Discoveries**: 30% for a rumour (an unknown item of the region becomes a known silhouette with its hint); a guardian's pool is discovered when it first falls.
- **Dry-streak rule**: after two wins with nothing new, the third is forced to give a drop, else a discovery, else material.
- **No farming**: gold, experience and material fall to 85/70/55/40% as the same foe fills the last eight wins, and recover as other foes are fought.
- **New Game Plus**: gold ×(1 + cycle), experience ×(1 + 0.5 × cycle), cores again.

Result keys: `xp gold shards items(=items_new) levels mastered first` (the existing overlay) and `materials discoveries mastery_ups[{id, slot, tier, text}] unlocks[{type, id, item}] shop_unlocks compensation repeat pity core taught`.

## 7. Economy

`Game.buy / sell / upgrade / mod / craft / buy_material`, each with a `*_block(id)` that says why not. Guards (all tested): cannot sell what is equipped, a favourite, a keepsake (`quest_item`), the Wayfarer's Blade, the last weapon, the last one-handed blade, or an id this version does not know; a one-of-a-kind item that was sold can be bought back for three times its sale price, so nothing is lost for good; nothing can be bought that is locked, owned or unaffordable; no currency or material goes below zero; costs rise with every level and are never zero; everything sells for less than it costs; rings and relics cannot be "upgraded" (it would change nothing the duel reads); an upgrade always changes a number the duel reads. Orren also sells shards (60) and the material of any cleared region (40–240), and buys neither back: a valve for gold late on, not a trade. Guardian Cores are never sold.

## 8. Save format and migration

`Game.SAVE_VERSION = 2`. On disk the per-item state is one record per item, apart from the definitions:

```
items: { "<id>": {owned, discovered, seen, level, mastery_xp, mastered, favourite, order, taught?, mods?{grip, ore, ore_id}, edge?} }
equipped: {slot: id|null}            # the loadout, all eleven slots
materials: {id: n}   shards, gold    # currencies
cosmetics: {slot: {finish, accent, look_as}}
rewards: {seed, pity, recent[], cores{}}   sold[]   challenges_done[]
```

In memory the same state stays in the fields existing code uses (`inventory`, `upgrades`, `mastery`, `mastered`, `favourites`, `mastery_taught`) plus `discovered`, `seen`, `mods`, `edge`; `Game._pack` / `_unpack` convert. `Game._migrate` accepts every earlier shape (no version field; version 1 flat lists; version 2), is idempotent, and drops nothing: unknown item ids, foes and fields are kept. From an older save: owned items count as discovered and seen; every guardian already ended gives its core; a weapon's upgrade level becomes its blade tier and it is given the ore that tier needs; alternative ids are rewritten to the stored ones; a shield worn with Oathbreaker comes off the arm and stays in the pack. Fixtures: `tests/fixtures/save_v0.json`, `save_v1_early.json`, `save_v1.json`. Previews and queries never write (tested against the profile and the file's bytes).
